# Kleiwell — автопостинг в Threads

Бот анализирует, о чём пишут мебельные производства в Threads, генерирует через
Claude смешные и вирусные посты, которые продвигают клей для мягкой мебели
[kleiwell.ru](https://kleiwell.ru), и публикует их — сам или по кнопке в Telegram.

```
анализ постов мебельщиков → генерация (Claude) → модерация → публикация в Threads
```

## Как это работает

Раз в `POST_INTERVAL_HOURS` часов запускается пайплайн:

1. **Анализ.** `keyword_search` по темам мягкой мебели собирает свежие посты
   отрасли. Результат кешируется на сутки — у Threads всего 500 поисковых
   запросов на скользящие 7 дней.
2. **Генерация.** Claude получает брендбук, свежие боли из ленты и список уже
   опубликованного, возвращает `POSTS_PER_RUN` вариантов структурированным JSON.
3. **Модерация.** Отсекаются посты длиннее 500 символов, с запрещёнными
   формулировками и пересказы уже опубликованного.
4. **Публикация.**
   * `AUTO_PUBLISH=0` (по умолчанию) — черновики уходят в Telegram с кнопками
     «🚀 В Threads» / «🗑 Пропустить».
   * `AUTO_PUBLISH=1` — первый прошедший модерацию пост публикуется сразу,
     в Telegram приходит уведомление с ссылкой.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить
python main.py
```

## Настройка

### Claude

`ANTHROPIC_API_KEY` — ключ с [console.anthropic.com](https://console.anthropic.com).
Модель по умолчанию `claude-opus-5`, меняется через `CLAUDE_MODEL`.

### Threads

Нужно приложение Threads в [Meta for Developers](https://developers.facebook.com/apps)
и долгоживущий токен (60 дней).

**1. Создать приложение.** developers.facebook.com → «Мои приложения» →
«Создать приложение» → сценарий использования **«Доступ к Threads API»**
(*Access the Threads API*).

**2. Выбрать разрешения.** В настройках сценария отметить:

| Разрешение | Зачем | Без него |
|---|---|---|
| `threads_basic` | базовый доступ | ничего не работает |
| `threads_content_publish` | публикация постов | публиковать нельзя |
| `threads_keyword_search` | анализ постов фабрик | бот переключится на боли из `brand.py` |

⚠️ **`threads_keyword_search` требует App Review.** Со стандартным доступом
(режим разработки + тестировщик) поиск возвращает **только посты самого
тестировщика**, то есть ваши собственные. Чтобы искать чужие — а именно это и
есть «анализ постов фабрик» — нужен Advanced Access через App Review, возможно
с верификацией бизнеса.

Пока этого нет, бот работает на болях из `brand.py`: посты пишутся, просто без
свежих формулировок из ленты. Собственные посты из выдачи поиска отфильтровываются,
чтобы бот не анализировал сам себя.

**3. Задать Redirect URI.** В разделе настроек Threads API. Meta принимает
**только https**, `localhost` не подойдёт. Проще всего указать собственный сайт,
например `https://kleiwell.ru/` — поднимать сервер не нужно, код авторизации
прилетит в адресную строку браузера.

**4. Добавить себя тестировщиком.** В разделе ролей приложения добавить свой
аккаунт Threads как Threads Tester, затем **принять приглашение** в самом Threads:
Настройки → Аккаунт → Веб-сайты и приложения. Без принятого приглашения
авторизация будет отклоняться.

**5. Получить токен.**

```bash
python get_token.py                 # threads_basic + threads_content_publish
python get_token.py --with-search   # плюс threads_keyword_search, если он одобрен
```

По умолчанию запрашиваются только два скоупа, которые работают сразу: если
попросить неодобренный `threads_keyword_search`, авторизация может быть
отклонена целиком.

Скрипт напечатает ссылку авторизации, примет вставленный адрес редиректа,
обменяет код на короткий токен, короткий — на 60-дневный, и выдаст готовые
строки `THREADS_ACCESS_TOKEN` и `THREADS_USER_ID` для `.env`.

Продлить токен до истечения 60 дней (аккаунту токена должно быть больше суток):

```python
from threads_api import ThreadsClient
print(ThreadsClient("СТАРЫЙ_ТОКЕН").refresh_access_token())
```

### Telegram

`TELEGRAM_TOKEN` от [@BotFather](https://t.me/BotFather), `TELEGRAM_CHAT_ID` —
чат, куда падают черновики (свой id или id группы). Команды бота:

* `/now` — прогнать пайплайн прямо сейчас
* `/limit` — остаток суточной квоты Threads и статус автопостинга
* `/start` — текущие настройки

## Брендбук

`brand.py` заполнен по данным сайта (`config.php`): марки **Клей Well 225** и
**215**, состав, расход, фасовка, температурный диапазон, цены и области
применения. Модель строит аргументацию строго по этим спискам — чего в
`brand.py` нет, того она не напишет.

**Сайт бот не читает.** Если на kleiwell.ru поменяются цена, фасовка или состав,
поправь `PRICING` / `SPECS` / `ADVANTAGES` в `brand.py`, иначе бот будет
публиковать устаревшие цифры.

### Про заявления о безопасности

Сайт заявляет «без вредных выделений **при затвердевании**» и «негорючий
**после высыхания**» — обе формулировки про готовый шов. Клей растворительный:
в момент нанесения он пахнет и горюч.

Поэтому модерация пропускает точные формулировки и режет расширенные — `без
запаха`, `нетоксичен`, `не горит`, `безвреден`, `можно детям`. Список — в
`BANNED_PHRASES`.

## Лимиты Threads

| Что | Лимит | Как учтено |
|---|---|---|
| Длина поста | 500 символов | модерация режет до публикации, генератор целится в 420 |
| Публикации | 250 за 24 ч | `/limit` и проверка перед каждым постом (`MIN_QUOTA_LEFT`) |
| `keyword_search` | 500 за 7 дней | кеш анализа на `MARKET_CACHE_TTL_HOURS` (24 ч) |

Публикация в Threads двухшаговая: сначала создаётся контейнер, он должен дойти
до статуса `FINISHED`, и только потом вызывается `threads_publish`. Контейнер
живёт 24 часа. Всё это внутри `threads_api.post_text()`.

## Файлы

| Файл | Что делает |
|---|---|
| `main.py` | пайплайн, Telegram-бот, расписание |
| `brand.py` | брендбук: продукт, боли, заходы, запреты |
| `generator.py` | генерация постов через Claude |
| `analyzer.py` | анализ постов мебельщиков + кеш + фолбэк |
| `threads_api.py` | клиент Threads Graph API |
| `moderation.py` | длина, стоп-слова, антидубли |
| `history.py` | что уже опубликовано |
| `config.py` | переменные окружения |

История и кеш лежат в `data/` (в git не попадают).

## Запуск на сервере

Бот — долгоживущий процесс (`run_polling`), для systemd:

```ini
[Unit]
Description=Kleiwell Threads bot
After=network-online.target

[Service]
WorkingDirectory=/opt/kleiwell
ExecStart=/opt/kleiwell/.venv/bin/python main.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Черновики, ожидающие кнопки, хранятся в памяти процесса — после перезапуска
старые кнопки перестают работать, бот об этом честно скажет. Опубликованные
посты в `data/history.json` перезапуск переживают.
